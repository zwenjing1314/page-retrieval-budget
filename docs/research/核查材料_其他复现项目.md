# 其他可复现项目的定向核查

核查日期：2026-11-05。范围：补充 Visual RAG Toolkit、Token Pooling、OmniColPress 之外的入口，并确认 DocPruner / Prune-then-Merge / AdaMerge 的公开代码状态。本文件是启动核查的证据补充，不是批准并行启动三个项目。

本轮读取作者论文、仓库网页和少量指定源码、Hugging Face 模型元数据；没有安装、克隆、下载模型或数据集、训练、编码、评分，也没有读取或修改 layoutpatch。下文“已核查”只表示静态证据，不能读成已在 Windows / RTX 3080 Ti 上跑通。

## 结论

补充检索找到了真正的作者复现仓库 **ColPali-Reproducibility** 和公开的 **ModernVBERT** 小模型，但前者的当前单数据集 CLI 有明确代码缺陷，后者完整训练成本很高。它们都不应仅凭标题和 README 取代已审查的唯一主项目。官方 ColPali + ViDoRe 是更直接的对照入口，但官方评价项目正在迁移，必须固定实现和评价协议。

建议只保留一种主执行路线。其他材料的角色分别是：ColPali-Reproducibility 用于学习复现与消融的做法；官方评价代码用于校准协议；ColModernVBERT 预训练推理作为显存不足时的备用模型。不要同时复现三套环境。

## 1. ColPali-Reproducibility：有作者完整代码，但不能称为开箱即用

**论文与来源。** Jingfen Qiao 等，*Reproducibility, Replicability, and Insights into Visual Document Retrieval with Late Interaction*，SIGIR 2025，3335–3345，[DOI](https://doi.org/10.1145/3726302.3730285)。本地指定 PDF 的脚注明确链接作者仓库 [JingfenQiao/ColPali-Reproducibility](https://github.com/JingfenQiao/ColPali-Reproducibility)。核查固定提交 `d42be15f9af2236e312aad476b2bc23d8beced2d`，MIT 许可证。

**实际存在的运行入口。**

- [`bash_RQ1/infer_reported_colpali_v1.3.sh`](https://github.com/JingfenQiao/ColPali-Reproducibility/blob/d42be15f9af2236e312aad476b2bc23d8beced2d/bash_RQ1/infer_reported_colpali_v1.3.sh)：调用 `vidore-benchmark evaluate-retriever`，模型 `vidore/colpali-v1.3`，ViDoRe v1 官方 collection，`test` split。这是预训练模型评价入口，无需重新训练。
- [`bash_RQ1/infer_reproduced_colpali.sh`](https://github.com/JingfenQiao/ColPali-Reproducibility/blob/d42be15f9af2236e312aad476b2bc23d8beced2d/bash_RQ1/infer_reproduced_colpali.sh)：使用作者复现模型 `JFJFJFen/colpali-PairwiseCELoss`。HF API 已确认模型公开、非 gated、非 disabled；核查 revision `99f69a5eae4b71173753e0b84984c467873438bf`。没有下载或验证权重。
- [`bash_RQ1/train_colpali-v1.3-ColbertCELoss.sh`](https://github.com/JingfenQiao/ColPali-Reproducibility/blob/d42be15f9af2236e312aad476b2bc23d8beced2d/bash_RQ1/train_colpali-v1.3-ColbertCELoss.sh)：真正的训练复现通过 `accelerate launch` 启动，脚本请求 4 张 RTX A6000 和 120G 主存，训练脚本、配置均为作者机器绝对路径。这里的资源是作业请求，不是实测峰值；`--time` 也不是实测耗时。

因此，**可以只评价公开 checkpoint，但不能把它叫作完整重做该论文的 RQ1 训练复现**。README 将 RQ1.1/1.2 与训练复现和单向量比较联系起来，需区分“论文训练过程”与“论文已发布模型的评价”。

**真实推理代码。** [`colpali_retriever.py`](https://github.com/JingfenQiao/ColPali-Reproducibility/blob/d42be15f9af2236e312aad476b2bc23d8beced2d/vidore-benchmark/src/vidore_benchmark/retrievers/colpali_retriever.py) 使用 `ColPali.from_pretrained(..., torch_dtype=torch.bfloat16, device_map=...)`、`.eval()` 和 `torch.no_grad()`；查询/页面推理可以设置 batch，结果搬回 CPU；`get_scores` 调用 `processor.score(..., device="cpu")`。所查入口没有强制 FlashAttention、DeepSpeed 或 Qdrant。Shell 中的 `#SBATCH` 是调度注释，抽取 CLI 后并不必然要求 Slurm；但不能据此保证 Windows 所有依赖可装。

**关键静态问题，不能忽略。**

1. [`main.py`](https://github.com/JingfenQiao/ColPali-Reproducibility/blob/d42be15f9af2236e312aad476b2bc23d8beced2d/vidore-benchmark/src/vidore_benchmark/main.py) 的单数据集分支写成 `if "syntheticDocQA_healthcare_industry_test" or ... in dataset_name:`。第一个非空字符串恒为真，所有单数据集都会进入特殊 token matching 分支，普通评价 `else` 不会运行。
2. 默认 `matching_type=""`，但 [`processing_colpali.py`](https://github.com/JingfenQiao/ColPali-Reproducibility/blob/d42be15f9af2236e312aad476b2bc23d8beced2d/colpali_engine/models/paligemma/colpali/processing_colpali.py) 的 `matching_score` 只给六种指定类型赋值，随后直接 `return score`。默认单子集命令会走到未赋值路径。这是代码推导，未实际执行。
3. 普通 [`evaluate_dataset`](https://github.com/JingfenQiao/ColPali-Reproducibility/blob/d42be15f9af2236e312aad476b2bc23d8beced2d/vidore-benchmark/src/vidore_benchmark/evaluation/evaluate.py) 返回 `(metrics, query_metrics, top_100_results)`，旧单子集普通分支却仍按单一字典处理。因此只修正第一个 `if` 还不够。
4. collection 的池化路径中，`query_metrics_savepath` 和 `run_results_savepath` 只在未池化时定义，之后却无条件写出；打开池化会有未定义变量风险。

**版本不是完全锁定的。** README 报告 Python 3.11.6 / PyTorch 2.5；根目录 `pyproject.toml` 约束 `transformers>=4.46.1,<4.47`，`requirement.txt` 仅有 `pip install transformers==4.46.1`。嵌入的 `vidore-benchmark/REPRODUCIBILITY.md` 仍是旧上游清单，包含 `transformers==4.41.2`、`torch==2.3.1`、`mteb==1.12.47`，与当前 fork 的约束不一致，并混有 Triton、NCCL、uvloop 等 Linux 环境条目。不能直接照抄为 Windows 锁定环境。

**采用判断：学习材料 / 后续对照，暂缓当第一个运行底座。** 优点是作者代码、公开 checkpoint、官方数据都存在；问题是单子集和池化正是我们需要的入口，而这些入口需要先修复。它比“自己重做数据和模型”更可复用，但不能仅因为标题叫 reproducibility 就认为比 Toolkit 更省心。

## 2. 官方 ColPali + ViDoRe：直接基线，需处理评价入口迁移

官方项目：[ColPali](https://github.com/illuin-tech/colpali)、[ViDoRe benchmark](https://github.com/illuin-tech/vidore-benchmark)，论文 [ColPali, arXiv:2407.01449](https://arxiv.org/abs/2407.01449)。这属于原模型及其基准的官方底座，不是新压缩论文。

本次固定 ViDoRe 主分支提交 `de1d88c14c31d9e0d761b7099fe6eb4f876f8912`。当前 README 明确：本仓库侧重多阶段 pipeline，旧单 retriever 路径保留但已弃用；单模型 ViDoRe v1–v3 评价推荐迁移到 MTEB。历史使用见 [`README_OLD.md`](https://github.com/illuin-tech/vidore-benchmark/blob/de1d88c14c31d9e0d761b7099fe6eb4f876f8912/README_OLD.md)，不能把最新版主分支与几年以前的安装教程随意拼接。

旧官方 CLI 明确允许单个子集，例如 `--model-class colpali --model-name vidore/colpali-v1.3 --dataset-name vidore/docvqa_test_subsampled --dataset-format qa --split test`。ViDoRe v2 使用 `--dataset-format beir`，其数据由 `corpus / queries / qrels` 三个配置组成。旧文档明确：v1 QA 会按查询文本去重；v2 BEIR 不去重。不同协议下的数字不能直接当作同一次复现结果。

官方现成数据和评测比自行从旧项目组装候选库更直接；但若选择这一底座，应先固定兼容的旧版本或完成当前 MTEB 入口的源码核查。本文件没有核实完整版本组合，也未执行任何命令，不把这段 CLI 当成本机可直接运行的保证。

**采用判断：作为评价协议核对来源和直接基线，不另开第二个并行项目。**

## 3. ModernVBERT：小显存备用模型，完整训练不适合本轮

论文：[ModernVBERT: Towards Smaller Visual Document Retrievers](https://arxiv.org/abs/2510.01149)，已读取指定本地 PDF，版本 v3（2025-12-16）；作者代码：[illuin-tech/modernvbert](https://github.com/illuin-tech/modernvbert)，固定提交 `d4727bde0525991585cc13ccdedecf32c69ed25c`，MIT。

模型是约 250M 参数的视觉文档编码器。官方 [ModernVBERT/colmodernvbert](https://huggingface.co/ModernVBERT/colmodernvbert) 提供晚期交互版本；HF 元数据确认公开、非 gated，revision `4c604428a6e1a7e33d0fb34837f0cdecbc22026e`。当前模型卡给出 Sentence Transformers `MultiVectorEncoder` 的 `encode_query` / `encode_document` / `similarity` 调用，要求 `sentence-transformers[image]>=6.0.0`；旧 ColPali engine 示例同时仍保留分支尚未合并的提示。这说明需要选定一条入口，不应混用新旧教程。

模型卡说明 FlashAttention 2 用于提高吞吐，另给 float32 示例；但本次没有把实现追到所有依赖，不保证 Windows 无需额外修改。模型图像处理采用图像分块及全局块，不能把其 token 网格直接当作 ColPali 32×32 网格。

代码仓库主要是训练配置/脚本；README 明确提醒依赖分支/子项目可能尚不稳定，并建议按 trainer 拆环境。论文报告最终模型训练约 2000 H100 GPU 小时，全部研究实验约 18000 H100 小时；表 4 给出对齐 1920h、一般对比训练 80h、文档专门训练 160h。**小模型不代表可以低成本重做它的全部训练。** 论文的 L4 / H100 编码速度也不能直接换算为 RTX 3080 Ti 耗时。

**采用判断：仅在 ColPali 的本机推理成本确实不合适时，考虑公开 checkpoint 推理作为备用；不复现其完整训练，不现在并行换模型。**

## 证据边界与下一步

所有候选的运行成功、Windows 依赖、实际显存、完整候选库处理与指标一致性均需后续小规模执行验证。当前最有把握的新增事实是：作者复现仓库和 checkpoint 存在，但关键 CLI 有静态错误；小模型公开，但训练代价不低；另外三篇压缩论文没有在本次定向检索中找到可直接采用的作者实验仓库。

下一步只应选择主报告确定的一套底座、一种模型、一个官方子集，先固定候选库和评价协议，再做完整向量与一种已有压缩的对照。复现成功是建立基线，不构成新研究贡献。
